# Використання засобів ШІ (Лабораторна робота 2):

Під час виконання цієї лабораторної роботи я використовувала ШІ-асистент (Gemini) як інструмент для розуміння сучасної архітектури навігації в Jetpack Compose, вирішення локальних помилок в Android Studio та підготовки до захисту коду. Нижче наведено хронологічний протокол нашої взаємодії.

### Етап 1: Аналіз вимог та проєктування архітектури
**Моя дія:** Я надіслала ШІ свій готовий код з Лабораторної роботи №1, текст завдання Лабораторної №2 та кілька фотографій з прикладом структури проєкту (файли `NavigationGraph.kt`, `HomeNavDisplay.kt`, використання `sealed interface`), яку необхідно було застосувати.
**Результат:** ШІ проаналізував фотографії і пояснив, що це підхід **Type-Safe Navigation** (Типізована навігація) з використанням бібліотеки `kotlinx.serialization`. ШІ надав покроковий план: які залежності додати в `build.gradle.kts` та як розділити логіку на графи (маршрути) і контейнер (`NavHost`). 

### Етап 2: Вирішення помилок імпорту за допомогою скріншотів
**Моя дія:** Під час написання коду для екранів, Android Studio підкреслила червоним імпорт іконки `Icons.AutoMirrored.Filled.ArrowBack`. Я зробила скріншот екрану з помилкою `Unresolved reference 'icons'` і надіслала його ШІ.
**Результат:** ШІ розпізнав помилку по скріншоту і пояснив, що ця іконка не входить до базового набору Compose. За його підказкою я додала залежність `androidx.compose.material:material-icons-extended` у Gradle, після чого помилка зникла.

### Етап 3: Перевірка вимог завдання та розширення функціоналу
**Моя дія:** Я попросила ШІ перевірити, чи точно моя поточна реалізація задовольняє умову "мінімум 2 переходи, 2 підекрани". Отримавши підтвердження, я вирішила ускладнити завдання і запитала: *"Чи можна реалізувати третій підекран (додаткові матеріали), на який буде перехід від детальної інформації по лекції?"*
**Результат:** ШІ оновив мій `sealed interface`, додавши маршрут `ExtraResources`. Ми налаштували багатоступеневу навігацію (`List` -> `Details` -> `ExtraResources`). ШІ пояснив, що завдяки методу `navController.popBackStack()` система запам'ятовує історію, і при натисканні "Назад" на третьому екрані користувач коректно повертається на другий, а не на самий початок.
